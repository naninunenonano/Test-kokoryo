# TEST Ver.0.3.233 調査・検証報告

基準：完成・公開済みTEST232、main b093d4b3299f640de4d48adc2298495311e9b362。今回の対象はVP到達通知の表示のみ。本番未変更。

## 調査結果

- checkEndgameTriggerは現在も実装され、自分の手番中に設定VP以上になるとendgameStarterを設定する。30固定ではなくgameSettings.winVPを使う。
- triggerNoticesの文とrenderSharedEndgameStatusの常設通知を使用。到達者、目標VP、残り最終ターン人数を表示し、全員の最終ターン後に結果へ切り替える。
- 過去TEST222（d25916d）のCSSにも上端固定のendgame-progressがあり、TEST229（8496342）の描画も同じ方式。過去の実機で正常だった時期や、不具合の発生開始版までは断定していない。
- 人間・Bot、29→30と29→31の到達・残り全員の進行・勝敗判定は正常。endgameStarterによる重複防止も正常。
- 通常の条件発動メッセージは描画後に消費される。Bot相手の閲覧画面では条件発動欄の描画へ進まないこともあるが、常設gameover通知は別処理で維持されている。
- 表示不具合を確認：到達通知は上端8px（スマートフォン幅は4px）、z-index1200。一方、TEST固定ヘッダーは上端0・不透明背景・z-index30000で、到達通知より前面にある。スマートフォンのヘッダー折返し時ほど通知へ重なる。

## 修正

TEST用ビルドの通知スタイルだけを補正。ヘッダーの実際の下端＋8pxへ配置し、通知のz-indexを30001にする。幅・高さを画面内へ収め、必要時は縦スクロールする。ヘッダーの大きさはResizeObserverと画面resizeで追跡する。結果画面の中央配置を壊さないよう、位置はCSS変数を通じてendgame-progressにだけ適用。

新しい到達イベント・ポップアップ・勝利条件を追加していない。ゲーム内部の全コードと元HTMLは、版番号を除き232とのハッシュ比較で不変であることを検証。232の資源表示・持ち時間300秒／回復60秒を再実装していない。
